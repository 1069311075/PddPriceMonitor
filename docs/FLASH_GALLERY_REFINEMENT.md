## 1. 本轮目标和范围

用户已经使用截图功能，现希望更容易找图、减少占用、方便清理。

本轮范围收敛为以下四项：

1. 图片占主导的三列相册网格。
2. 显式选择、长按多选、全选/取消全选、删除所选截图。
3. 新截图适度缩小、压缩，浏览时控制解码内存。
4. 按 30 天、90 天或全部截图进行手动清理。

界面名称从“高清截图”简化为“截图”。功能相关的提示和无障碍名称一并调整。保留“圆角方柱”悬浮按钮的外观、上段 OCR / 下段截图分工及已经完成的防误触、新帧获取逻辑。

不增加云端、本地大模型、自动识别配置、商品归类、自动清理或额外压缩设置页。不重构整个项目，不修改旧 OCR 记价业务。用户设备为小米 17 Ultra，16 GB 内存。

## 3. 相册式布局

### 网格页

- 手机竖屏默认三列，列间/行间约 2–4dp，外侧留少量边距；不要再使用一张图占一整行的卡片。
- 图片自身是主内容。移除每张图旁边的尺寸、MB、重复时间、导出和删除按钮，以及大块卡片留白。
- 普通浏览态顶部保留“截图”、可发现的“选择”、简洁的“清理”和返回/完成；布局过窄可把清理放进明确的更多菜单，但不能把选择功能只藏在长按里。不保留常驻解释性副标题。
- 操作成功或失败用短暂反馈，不长期挤占图片区域。大图打开时，反馈也必须在用户当前能看见的层显示，不能只显示在被大图 Dialog 遮住的网格层。
- 按拍摄时间倒序，按本机时区日期分组，组标题占整行：今天、昨天、月日；跨年份时显示年份。
- 日期只放分组标题，不在每张图下面重复显示。
- 缩略图保留完整截图比例，不能用正方形居中裁切把底部配置、价格裁掉。不要为铺满格子拉伸图片。
- 采用惰性网格及稳定 id，日期标题跨整行。屏幕尺寸变化时保持合理列宽，避免挤压和横向溢出。
- 相册仍打开但应用切到拼多多截图后再回来，要刷新图片列表，而不只是刷新主页张数。刷新与选择状态按下节规则协调。

### 选择与批量删除（本稿补齐的必做项）

**进入和退出：**

- 点击顶部“选择”进入选择态，初始可为 0 张；普通浏览时长按图片也能进入并选中该图。
- 使用独立的选择模式状态，不把“选中集合非空”当作选择模式开关。取消最后一张后仍停留在选择态，可继续选择其他图片。
- 普通态点图查看大图；选择态点图只切换选中/未选中，不打开大图，也不因长按再触发一次单击。
- 选择态显示空心勾选位、已选勾选、已选张数和可见的“取消”；不选时不把角标永久堆在所有图片上。
- “取消”清空选择并退出，系统返回键在选择态先退出选择，再次返回才离开相册。关闭确认框的返回操作应只关闭确认框。

**选取范围：**

- 提供“全选 / 取消全选”，作用于当前相册实际存在的全部记录，不仅是屏幕内可见单元；0 张或空列表不产生可执行删除。
- 选择态的日期标题可以“选择当日 / 取消当日”，用来快速选择一组；不覆盖其他日期已有选择。
- 全选是当前 id 集合的一次快照。之后新加入的截图不自动选中；选中 id 在刷新后与现存 id 取交集，已不存在的条目不留下虚假计数。
- 横竖屏或短暂切到外部文件选择器再回来，选择态和勾选结果应保留。进程被系统终止后的复杂恢复不作为本轮扩展任务。
- 不要求滑动连选、手势框选或新增搜索/收藏/回收站，先把基础选图流程做完整。

**执行与结果：**

- 选择态提供统一的“删除所选”；无选中时置灰，选择 N 张时显示计数。不在每张图片旁边添加删除按钮。
- 点击删除时把选中 id 集合冻结为待确认快照，确认框准确显示“删除选中的 N 张截图？”；取消确认不丢失勾选。
- 确认后只删除快照里的截图及其附属文件，不改为按日期、不重新计算全选集合。新截图不得被连带删除。
- 删除过程中防止再次执行和修改本次待处理集合。通过 finally 恢复忙碌状态，处理异常，不因失败把界面永久锁在“正在删除”。
- 单删、所选批删和按时间清理共用已经存在的按 id 删除能力。结果需能识别成功、失败和已经不存在的 id，不能只返回数量后丢掉失败项。
- 全部成功后清空选择并退出选择态；部分失败时移除成功项，保留失败项的勾选，反馈数量并允许直接重试，不能让用户重新寻找失败的图片。
- 刷新相册、日期标题和入口计数，尽量保持原滚动位置。删除整组后，空日期标题自动消失；删除最后一张后进入空态并退出选择态。
- 选择态与按时间清理不同时执行；清理仅在普通浏览态提供，避免用户以为“30 天前”只作用于已选图片。

**导出范围：**

- 本轮必须保留大图中的单张导出。批量导出/分享是可选后续项，不与“批量删除”混为一谈，不据此扩展本轮为完整文件管理器。

### 大图页

- 点图打开大图，可以左右翻看当前相册中的前后截图。
- 仅保留简短拍摄时间及必要的返回、导出、删除操作，不常驻宽高、文件大小和手势教学文字。
- 保留双指缩放与双击放大；放大后平移不要与翻页抢手势。换图重置上一张缩放和偏移。
- 返回网格保留滚动位置，不跳回顶部。
- 删除当前图后更新列表和入口计数，并显示合理的相邻图；没有图片时退出大图进入空态。
- 当前查看对象以稳定 id 为准，Pager 设置稳定页面 key；前面新增/删除其他图片时，不因下标变化跳到另一张。删除当前图时优先显示原顺序下一张，没有下一张再显示上一张。
- 导出、删除针对用户此刻看到的图片；不能使用最初打开时的旧 Entry 或旧页码误操作另一张。
- 返回键先关闭确认/清理弹层，再退出大图或选择态，最后离开相册，避免一次返回关闭所有层。

增加图片占比的目标是帮助辨认，不承诺同屏张数必然翻倍。完整竖图会占一定高度，这比裁掉配置内容更重要。

## 4. 新截图压缩与浏览内存

### 新截图保存

- 将本轮之后的新截图默认保存为 **JPEG，quality 85，长边不超过 1920 像素**。
- 缩放保持比例、尺寸取有效整数，小于上限的截图不放大，横屏同样按长边限制。
- 参数是本轮起始标准。用几张真实配置页放大检查小字和价格：明显不可辨认时再针对性微调，不无依据扩大到全分辨率。
- 只保留压缩后的主图和列表缩略图，不同时隐藏保存一份全尺寸 PNG，否则无法达到减少存储占用的目标。
- 压缩发生在新截图归档路径，不降低旧 OCR 识别时使用的画面分辨率。
- 图片缩放、编码、元数据和缩略图写入放 IO/后台执行；复用目前隐藏控件、等待新帧和暂存目录归档机制，异常回收资源、恢复控件。
- 不把文件 MB 变小等同于解码内存变小。编码格式和像素尺寸两项都需要生效。

### 缩略图及解码

- 网格仅用缩略图，不为每个单元加载主图；根据网格实际显示尺寸和像素密度选合理缩略图大小，避免新网格发虚或过度解码。
- 新缩略图保留完整长宽比，旧缩略图仍可使用；缺失时可按需重建，重建不改主图。
- 大图按屏幕需求采样解码，并给旧大 PNG 设置合理的解码尺寸上限；不能为生成小预览先完整解码所有原图。
- 翻图只加载当前图和有限的必要邻图，避免一次预加载整个相册的主图。
- 正确处理取消/换图时返回的旧加载结果，释放不再使用的 Bitmap，不能提前回收仍被 Compose 绘制的图片。

## 5. 旧 PNG 与新 JPEG 并存

旧截图不批量压缩、不迁移目录、不改 UUID 和 capturedAt；继续列举、查看、删除及导出。

可以继续使用 `filesDir/hd_captures/<uuid>/` 和现有类名。新记录使用例如 `original.jpg`，metadata 写入真实 path、mime=`image/jpeg`、保存后的宽高和实际 sizeBytes。

- 如提升 schemaVersion，读取端兼容旧版本；旧记录缺少 path/mime 时按已有 PNG 约定回退。
- 截图记录的身份必须对应真实归档目录；损坏的 metadata.id 不得把查看或删除引向另一条记录。格式字段与可识别的文件格式明显矛盾时，按受控规则修复读取或标为异常，不能导出伪格式文件。
- 图片路径由单条记录的元数据或受控回退规则解析，查看、删除、导出使用同一份解析结果。路径必须留在对应归档目录内。
- 旧 PNG 导出为 `.png` / `image/png`，新 JPEG 导出为 `.jpg` / `image/jpeg`；系统文件选择器的 MIME 也要匹配所选记录。
- 导出复制已保存主图的原始字节，不再次有损压缩，不把 JPEG 字节冒充 PNG。
- “导出原图”等容易让人误解仍有一份无损源图的文案，统一改为“导出截图”或“导出”。
- 单条新格式记录损坏不应导致整个相册打不开；对失败项给出可见的占位/错误反馈。

## 6. 手动按时间清理

顶部“清空”改为“清理”，打开简洁的选项面板：

1. 删除 30 天以前。
2. 删除 90 天以前。
3. 删除全部截图。

不设置自动执行任务，也不进入页面就删图。

### 截止时间定义

- 用 metadata 的 **capturedAt**，不用文件修改时间来判断年龄。
- capturedAt 缺失或无效时标为“日期未知”，网格放在单独组；30/90 天清理跳过并说明跳过数量，不能用目录修改时间推断后删除。用户仍能手动选择删除；“全部”确认可包含这些已归档记录。
- 按操作时手机的本机时区，取“今天减 30/90 天”的零点为截止时间。仅删除 `capturedAt < cutoff` 的截图，截止当天零点起的截图保留。
- 例：2026-10-17 操作“30 天以前”，确认文案写“将删除 2026年9月17日 00:00 以前的……”，避免“一个月”与自然月的歧义。
- 截止时间在生成本次预览时固定，确认期间跨午夜不应静默扩大删除范围。

### 预览、执行和反馈

- 点击选项后先展示候选张数和预估释放空间，再确认执行。例如“将删除9月17日00:00以前的24张截图，预计释放约38 MB”。数字来自实际数据，不能写死。
- 预估至少统计候选主图大小，文案注明“约”；需要时包含附属文件实际大小。没有候选时显示“没有符合条件的截图”，不弹空删除确认。
- 确认只针对预览的候选 id 集合执行，新增截图不因执行期间重新遍历而被扩大纳入。“全部”也遵守这一点。
- 删除每条候选的主图、缩略图、metadata，范围限定截图归档目录。禁止删除 OCR 数据库、旧 OCR 附图或其他照片。
- 不把正在写入的 `.staging-*` 目录作为清理对象。检查当前 `listEntries()/cleanupStaging()` 与 save 的并发，不能把进行中的暂存目录当作中断残留删掉；必要时以互斥或明确的过期判断保护。
- 清理期间防重复确认，不阻塞主线程。删除失败要统计并反馈“删除 N 张、失败 M 张”，不能忽略返回值仍报全部成功。
- 完成后刷新当前相册、日期分组、入口计数和当前查看图；重复执行同一范围后应正确显示无候选或仅剩失败项。
- 取消任意清理预览不丢失浏览位置；执行异常要恢复忙碌状态并提供可见反馈，部分失败可针对失败 id 重试，不把成功项重复纳入。

## 8. 有限且明确的验收

完成以下检查即可交付，不在没有新修改/新失败的情况下反复跑同一批验证：

1. 构建成功；相册按日期三列显示，仅图片和日期分组，点击/翻图/放大/返回位置正确。
2. 新图真实编码为 JPEG，长边 ≤1920、不放大小图；尺寸、大小、路径和 MIME 与实际文件一致；配置和价格小字可辨。
3. 旧 PNG 与新 JPEG 混合时均能打开、删除和以正确格式导出；旧图文件保持不变。
4. 测试 30/90 天截止前、恰好截止时刻、截止后的样例；候选与确认文案一致，边界后的图保留。
5. 测试无候选、取消、全部、部分删除失败及保存同时进行；不扩大候选范围，不删活跃暂存，不误报结果。
6. 清理后相册和计数正确刷新，旧 OCR 记录、附图不受影响；圆角方柱按钮及原有截图流程正常。
7. 显式进入、长按进入、勾选/取消、全选/取消全选、按日期组选择、0 张保持选择态、取消/返回退出均正确；清理与选择态不混用。
8. 删除所选的确认对象固定；取消保留勾选，部分失败保留失败项可重试；新增截图不误选、不误删，刷新后无幽灵选中项。
9. 列表插入/删除后大图仍定位原 id，操作针对当前图；前后台返回、旋转、大图返回不无故丢失选择和浏览位置，顶层可见导出/删除反馈。
10. 日期未知和损坏记录可见、可手选删除；按时间清理不根据推测日期删除；异常和取消不会造成永久忙碌或重复执行。

时间边界和删除结果可做少量针对性测试；压缩质量、缩放手势及滚动体验用可用设备实际检查。优先使用临时测试记录验证清理，不为测试删除用户真实图片。没有设备或无法执行的检查标为未验证，不无限等待。

交付修改摘要、构建结果、APK 实际路径、已执行与未执行的检查，以及少量截图压缩前后尺寸/体积和文字可读性对比。不捏造设备、内存或准确率数据，不自动提交、推送或发布。

## 9. 本次全流程复核结论
